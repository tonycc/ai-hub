# AI Hub 管理端前端页面设计规范

## 1. 文档目的

本文档用于约束 AI Hub 平台和内部轻应用的管理端页面设计与开发，确保不同页面在布局、信息层级、交互方式和响应式行为上保持一致。

本规范适用于 Vue、React 或其他 Web 管理端页面。业务应用可以在不破坏公共布局、组件和交互约束的前提下补充领域字段与业务操作。

## 2. 页面整体布局

### 2.1 页面骨架

所有管理端页面默认采用统一应用壳层：

```text
PlatformLayout
├── 左侧主导航（可折叠）
├── 顶部全局导航
│   ├── 面包屑与当前页面标题
│   ├── 全局搜索
│   └── 工厂、通知、用户和身份操作
└── 主内容区
    ├── 页面工具栏（PageHeader）
    │   ├── 页签行（可选）
    │   └── 搜索、筛选、结果统计和操作行
    └── 业务内容区
```

### 2.2 应用壳层尺寸

| 区域 | 规范 |
| --- | --- |
| 左侧导航展开宽度 | 232px |
| 左侧导航收起宽度 | 72px |
| 顶部全局导航 | 高度 64px，保持吸顶 |
| 主内容左右间距 | 默认 12px |
| 顶部导航左右间距 | 默认 24px |
| 页面根容器 | `width: 100%`，不设置与信息量无关的窄 `max-width` |
| 内容区背景 | 使用平台浅灰背景，内容面板使用白色 |
| 区块间距 | 默认 12px，复杂区块可使用 14—16px |

主内容必须使用应用壳层提供的可用宽度。禁止为了居中而额外设置窄容器，避免大屏出现大块空白。

### 2.3 顶部全局导航

顶部导航只负责全局上下文，不承载具体业务筛选：

- 左侧显示面包屑和当前页面标题。
- 中间提供跨应用全局搜索。
- 右侧提供工厂/环境选择、消息入口、当前用户和身份菜单。
- 页面标题只在此处展示一次，页面内容区不得再次渲染页面主标题、副标题或重复说明。
- 顶部导航使用深灰蓝作为平台导航色，主要业务操作使用橙色强调色。

### 2.4 页面工具栏 `PageHeader`

`PageHeader` 是所有页面的统一首行容器，必须与顶部全局导航保持同宽，不得嵌套在窄卡片或带额外左右留白的容器中。

有页签的页面固定采用两行结构：

```text
┌──────────────────────────────────────────────────────┐
│ 页签行：对象 / 来源绑定 / 行为与规则 / ...             │
├──────────────────────────────────────────────────────┤
│ 搜索、筛选、结果统计                         主要操作 │
└──────────────────────────────────────────────────────┘
```

规范如下：

- 第一行只放页面级页签，不放搜索框、筛选框和大段说明文字。
- 第二行放搜索、筛选、结果统计、刷新、导出、新建等操作。
- 页签和工具栏高度由实际内容自动撑开，不设置固定高度压缩内容。
- 空间不足时自动换行，不使用横向滚动容器；工具栏不显示原生滚动条。
- 页签字号统一为 16px，按钮点击高度约 46px，激活态使用品牌橙色底部 2px 指示线。
- 搜索和筛选控件靠左排列，主要操作靠右排列；移动端操作自然换行并保持按钮顺序。
- 工具栏中不得放页面说明横幅、平台边界宣言或重复性产品介绍。
- 业务告警、异常提醒和实时状态可以作为内容区信息卡保留，但必须是可处理的业务信息，而不是静态说明。

推荐的组件调用方式：

```vue
<PageHeader title="权限与安全">
  <template #tabs>
    <div class="page-tabs">
      <button class="active">角色管理</button>
      <button>权限点目录</button>
      <button>数据范围</button>
    </div>
  </template>

  <el-input v-model="keyword" clearable placeholder="搜索角色" />
  <el-select v-model="status">...</el-select>
  <span class="toolbar-count">24 个角色</span>

  <template #actions>
    <el-button>导出</el-button>
    <el-button type="primary">新增角色</el-button>
  </template>
</PageHeader>
```

没有页签的页面直接使用第二行；没有搜索或筛选的页面，只保留操作区，不人为创建空白占位。

## 3. 页面类型布局规范

### 3.1 列表页

适用于应用、用户、角色、消息、审计和服务记录等平台页面。

结构：

```text
PageHeader
├── 页签（可选）
└── 搜索 / 筛选 / 统计 / 操作
可选指标摘要
内容面板
└── 数据表格
    └── 底部结果数和分页
```

要求：

- 搜索、筛选和状态切换全部位于 `PageHeader`。
- 表格使用项目统一的 Element Plus 表格组件，不使用原生 `<table>`。
- 主数据列使用弹性宽度；状态、版本、时间和操作列使用合理固定宽度。
- 表格默认宽度 100%，只有总列宽确实超出视口时才允许表格自身横向滚动。
- 必须有加载态、空态、错误反馈、无权限态和分页状态。
- 操作列位置稳定，文案保持一致；危险操作必须二次确认。

### 3.2 卡片网格页

适用于应用中心、AI 员工、平台能力和服务入口。

结构：

```text
PageHeader
可选指标摘要
卡片网格
└── 业务卡片 / 新建卡片
```

要求：

- 卡片宽度随可用空间自适应，桌面端优先使用 2—4 列。
- 卡片内部信息顺序固定为：身份/名称、状态、关键指标、边界或标签、主要操作。
- 卡片操作不得只依赖悬停显示；键盘和触控设备必须可访问。
- 卡片中的说明应服务于对象识别，不使用独立说明横幅替代卡片信息。

### 3.3 详情页

适用于应用详情、能力详情和服务记录详情。

结构：

```text
详情返回与操作栏
对象身份和状态
业务流程/状态轨迹
主内容 + 侧栏
页签内容（如有）
```

要求：

- 详情页顶部显示业务编号、对象名称、状态、负责人和关键风险。
- 详情页的页签字号、激活态和交互方式与 `PageHeader` 页签保持一致（16px，点击高度约 46px）。
- 只读来源、版本、更新时间和证据链必须明确展示。
- 破坏性操作必须二次确认，并说明影响对象、原因和后续动作。

### 3.4 工作台/仪表盘

适用于工作门户、能力总览和运营页面。

结构：

```text
PageHeader
告警或待处理提醒（仅在存在真实业务事项时显示）
指标卡
主要工作区
辅助工作区/趋势/状态
```

要求：

- 指标卡用于快速判断，不替代列表和详情。
- 指标必须包含名称、数值、单位、时间范围或比较基线。
- 告警卡必须有明确对象、风险、时限和处理入口。
- 纯粹解释产品理念、平台边界或实施原则的横幅不应放在工作台内容区。

### 3.5 表单、抽屉和弹窗

- 新建/编辑标题必须包含动作和对象，例如“新建角色”“编辑应用环境”。
- 必填标识、字段提示、字段级错误和提交状态必须清楚。
- 复杂字段分组使用分区标题或描述列表，不使用大段说明横幅。
- footer 操作顺序统一为“取消”在左、“提交/保存”在右；主要操作使用橙色。
- 抽屉和弹窗支持键盘操作、焦点管理和 Escape 关闭。
- 清空字段必须明确传递 `null` 或项目约定的清空值。

## 4. 通用模块设计规范

### 4.1 页签

- 页面级页签放在工具栏第一行；内容区页签只用于详情内部上下文切换。
- 页签文案使用简短名词，避免句子和长说明。
- 激活态同时使用颜色、字重和底部指示线表达，不只依赖颜色。
- 页签过多时自动换行，禁止在工具栏中创建横向滚动条。
- 页签按钮必须使用真实 `<button>` 或项目统一按钮组件，并提供清晰文本。

### 4.2 搜索与筛选

- 搜索框放在工具栏第二行最左侧，placeholder 说明可搜索字段。
- 筛选项按业务决策顺序排列：状态 → 类型/来源 → 组织/负责人 → 时间范围。
- 结果数量放在筛选控件之后，使用弱化文字，不抢占主要操作视觉焦点。
- 筛选必须真正影响列表/卡片数据，不能只做视觉原型。
- 清空筛选后恢复默认结果；没有结果时提供明确空态和清除筛选入口。

### 4.3 按钮与操作

- 每个页面最多一个主操作，放在工具栏第二行右侧。
- 次要操作使用默认按钮或文字按钮，导出、刷新等不应与主操作竞争。
- 图标按钮必须有可访问名称或 tooltip。
- 没有权限的写操作不渲染，不能只渲染后禁用。
- 破坏性操作使用二次确认；失败反馈说明对象、原因和下一步。

### 4.4 指标卡

- 指标卡使用统一圆角、边框和内边距。
- 数值字号明显高于标签，单位与数值保持同一语义层级。
- 辅助信息必须说明同比、环比、目标或更新时间。
- 指标卡不承载复杂交互；点击后进入对应列表或详情。

### 4.5 表格

- 表头使用浅灰背景，行高和分隔线保持统一。
- 长文本默认截断并提供详情查看；业务编号使用等宽字体。
- 状态使用 `StatusTag` 或同等公共组件，文字与颜色同时表达。
- 空值统一使用 `—`，不能通过空白造成列错位。
- 分页和结果统计放在表格底部，不能另起一套分页样式。

### 4.6 状态、反馈与空态

页面必须覆盖以下状态：

| 状态 | 设计要求 |
| --- | --- |
| 加载中 | 保持页面结构，使用骨架屏或表格加载态 |
| 空数据 | 说明当前范围无数据，并提供下一步或清除筛选入口 |
| 错误 | 说明对象、原因和重试动作 |
| 无权限 | 不渲染无权限写操作，内容区明确说明访问权限 |
| 成功 | 对象级反馈，说明已完成的动作 |
| 不可用/降级 | 展示来源、更新时间、降级范围和恢复建议 |

颜色不能作为唯一状态表达方式，必须同时提供文字、图标或结构变化。

## 5. 响应式与滚动规范

- 桌面端优先，至少保证 1366px、1024px、768px 和 390px 宽度可用。
- 700px 以下工具栏改为纵向排列，搜索和筛选控件默认占满可用宽度。
- 页签和筛选控件空间不足时自动换行，工具栏高度随内容增长。
- 工具栏不使用 `overflow-x: auto` 或 `overflow-y: auto`；不得因为固定高度导致内容被截断。
- 页面和内容区可以继续使用滚轮、触控板和键盘滚动，但不显示原生滚动条视觉轨道。
- 只有表格、代码块、长文本或明确的数据容器在内容本身超出时才允许局部滚动。
- 禁止使用负 margin、固定宽度或绝对定位制造横向页面溢出。

## 6. 视觉令牌

优先复用 `src/styles/index.css` 中的令牌，不在单个页面随意硬编码。

| 令牌 | 用途 |
| --- | --- |
| `--brand-900` | 平台导航深色背景 |
| `--brand-800` | 导航、深色信息块 |
| `--accent-500` | 主操作、激活线、强调状态 |
| `--accent-100` | 主操作浅色背景 |
| `--ink-900` | 主文本 |
| `--ink-700` | 次主文本 |
| `--ink-500` | 辅助文本 |
| `--line` | 边框和分隔线 |
| `--surface` | 内容面板白色背景 |
| `--content-gutter` | 页面内容间距 |
| `--header-gutter` | 顶部导航和工具栏左右间距 |

推荐字号层级：

- 页面/对象名称：16—20px。
- 页签：16px；主要控件和表格表头：13—14px。
- 表格正文和卡片正文：12—14px，按信息密度调整。
- 辅助说明和元数据：10—12px；业务信息不得使用 7—9px 字号。

## 7. 开发实现约束

- 页面优先复用 `PlatformLayout`、`PageHeader`、`StatusTag`、`MetricCard`、表格、抽屉和弹窗组件。
- 新页面必须补充路由标题元数据，并使用 `PageHeader` 作为页面首行容器。
- 新增页签必须使用 `PageHeader` 的 `#tabs` 插槽；搜索/筛选放默认插槽；主要操作放 `#actions` 插槽。
- 不得在页面内部重复实现全局导航、页面标题、工具栏宽度和滚动行为。
- 不得新增纯说明性横幅；如果信息需要长期治理，应转化为字段、状态、指标、详情或可执行提醒。
- 修改管理端页面后至少执行 `npm run build`，并在桌面端和移动宽度检查自动换行、空态、错误态和操作权限。

## 8. 页面验收清单

- [ ] 页面标题只出现在顶部全局导航。
- [ ] 页面根容器和工具栏与顶部导航同宽。
- [ ] 页签和搜索/筛选已经分为两行。
- [ ] 工具栏高度由内容自适应，空间不足自动换行。
- [ ] 工具栏无横向或纵向滚动条，内容没有被截断。
- [ ] 搜索、筛选、状态切换真正影响内容区数据。
- [ ] 主操作位置稳定，权限和危险操作符合规范。
- [ ] 表格、卡片、详情、弹窗使用公共组件和设计令牌。
- [ ] 已覆盖加载、空数据、错误、成功、无权限和不可用状态。
- [ ] 已通过项目构建和响应式检查。
