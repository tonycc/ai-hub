# M3 平台公共能力实施基线

## 1. 文档目的

本文档是 M3 平台公共能力的实施与验收基线，覆盖管理端信息架构、角色权限矩阵、数据边界、公开契约和 UAT 用例。M3 只建设平台公共能力；中性参考应用仅用于契约一致性验证，不作为试点或真实业务应用交付。

## 2. 平台边界

平台持有并允许管理的数据包括：

- 身份映射、组织关系、平台角色和应用授权角色；
- 应用注册、环境入口、OIDC 回调、能力集、scope、凭据元数据和版本；
- 通知配置、通知请求状态和公共 API 调用审计；
- OpenAPI、SDK 示例、沙箱参数和一致性认证结果；
- 由应用数据导出契约汇聚的只读平台数据。

平台不得持有或提供编辑入口的数据包括：

- 真实业务领域字段、领域状态机和业务规则；
- 真实业务应用的可写业务主表；
- 外部应用数据库凭据；
- OIDC 客户端明文密钥。凭据明文只在创建或轮换成功的响应中返回一次，平台库仅保存不可用于认证的元数据。

平台角色分配支持两种资源范围：

- 全局范围：适用于平台管理员、安全审计员和平台运维；
- 应用范围：适用于应用开发者。服务端必须校验请求资源的 `application_id` 与角色分配范围一致。

## 5. 应用授权模型

应用授权与平台管理权限相互独立：

1. 权限点属于某个应用的公开授权契约，例如 `example.record.read`。
2. 应用角色聚合一组权限点。
3. 用户角色分配绑定数据范围，数据范围由类型和 JSON 参数组成。
4. `/me/permissions` 返回直授权限与角色权限的并集，且始终受应用边界约束。
5. 高风险动作继续通过在线授权决策 API 校验；应用本地仍负责对象级最终检查。

M1 的直授权限在兼容期保留；M3 管理端默认使用角色分配模型，新旧模型均不得跨应用泄漏。

## 6. 凭据与密钥边界

- authentik 是 OAuth2/OIDC 客户端凭据的事实来源。
- 平台使用独立、最小权限的 authentik 自动化身份管理应用客户端；该身份不得承担平台门户登录或业务 API 调用。
- 平台数据库只保存 `client_id`、外部 provider 标识、状态、版本、时间和非敏感提示。
- 创建或轮换时生成的新密钥只返回一次，不写入审计元数据、不写日志、不进入页面状态持久化。
- 吊销通过替换外部密钥并禁用平台服务主体绑定实现；旧密钥不能再换取令牌，已签发令牌也会被平台应用绑定检查立即拒绝。
- 平台门户使用独立 OIDC 客户端，任何业务应用凭据轮换均不得影响门户登录。

## 7. 通知、审计与开发者能力

通知配置按应用和渠道管理。测试送达使用与公开通知 API 相同的服务路径，并产生可关联的审计记录；测试接口不得绕过幂等和收件人检查。收件人选择通过应用范围内的 `platform.notification.write` 权限单独授权，只返回用户标识、稳定 subject 和显示名，不借用全局身份治理读取权限，也不暴露邮箱、组织或角色信息。

审计表保持追加写：运行时角色只允许 `INSERT` 和受管理 API 使用的 `SELECT`，仍禁止 `UPDATE` 与 `DELETE`。所有管理写操作至少记录操作者、动作、目标、结果、请求标识和不含密钥的元数据。

开发者中心只发布版本化公开资产：

- OpenAPI 契约及版本、摘要校验值；
- Python SDK 和最小接入示例；
- 本地沙箱入口、测试身份说明和故障排查；
- API-only、数据汇聚两种可独立选择的一致性配置。

API-only 是默认且最小的接入方式，不要求应用部署导出接口或 ingest 组件。

数据汇聚认证不跨库读取外部应用数据，而是导入运行门禁产生的摘要证据。证据按 SHA-256 内容摘要寻址，记录场景、结果、环境、契约版本和观测时间；数据汇聚配置只接受 30 天内且覆盖相应场景的成功证据。摘要用于检测意外篡改和关联制品，不等同于数字签名或不可抵赖证明。

运维中心展示应用入口检查结果、数据来源位点滞后、版本缺口、对账差异和检查点年龄。诊断不得修改应用配置或操作外部应用数据库。

## 8. M3 UAT 用例

### UAT-01 平台管理员注册应用

平台管理员注册一个中性应用，配置本地环境、入口、回调、`API_CLIENT` 能力和 scope，发布版本后能从公开应用查询 API 获得一致结果。无应用写权限的角色看不到写操作，直接调用写 API 返回 `403`。

### UAT-02 平台管理员配置授权

平台管理员创建应用角色、关联权限点并向用户分配 `OWNED` 数据范围。目标用户的权限快照包含该角色权限，未分配用户和其他应用均不可见。

### UAT-03 应用开发者完成 API-only 认证

应用开发者从开发者中心获取 OpenAPI、Python SDK 和沙箱参数，仅启用 `API_CLIENT`，完成 OIDC 登录、`/me`、权限快照和通知 API 的一致性检查。

### UAT-04 应用开发者按需启用数据汇聚

应用开发者为所属应用启用 `DATA_INGEST`，能够看懂所需基础设施和失败恢复规则；仅 API 配置不出现数据导出强制项。

### UAT-05 安全审计员轮换和吊销凭据

安全审计员轮换中性参考应用凭据，新密钥只展示一次，旧密钥不能再换取令牌；吊销后服务主体被平台立即拒绝。操作前后审计链完整且不包含密钥。

### UAT-06 平台运维诊断异常

平台运维能从运维中心区分应用入口不可用和数据同步滞后，获取明确的对象、时间、原因及下一步运行手册链接，且不能修改应用配置。

### UAT-07 全角色验证数据边界

四类角色均能明确区分平台配置数据、只读汇聚数据和外部业务数据；管理端和 API 中不存在真实领域字段、领域状态机、业务规则或业务主表写入口。

## 9. 验收记录要求

每个用例记录执行角色、开始与完成时间、是否成功、错误次数、术语误解、查找信息耗时和证据链接。M3 发布门槛为：

- 四类角色的适用任务全部通过；
- API-only 和数据汇聚一致性矩阵全部通过自动化检查；
- 不存在 P0 级权限泄漏、数据丢失或公开契约错误；
- 全量后端测试、静态检查、前端构建和关键页面浏览器验收通过。

实际执行结果及问题闭环见 [M3 UAT 报告](m3-uat-report.md)。
