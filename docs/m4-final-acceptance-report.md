# M4 生产准备最终验收报告

## 1. 验收结论

2026-08-14，M4-01 至 M4-06 全部完成，生产运行基线、恢复能力、指标告警、可逆发布、凭据轮换、性能安全和公共依赖故障门禁均达到已批准目标。平台代码与运行基线可以进入具体生产环境的部署实例化阶段。

本结论是“生产准备基线通过”，不是对任意尚未配置的生产环境直接签发上线许可。正式上线仍需在目标主机注入真实密钥与 HTTPS 域名、启用异机备份和告警责任路由，并重跑目标环境门禁。

## 4. 高可用与容量结论

[ADR-031](adr/ADR-031-standard-single-node-production-tier.md) 决定首个生产档位继续采用单主机 Docker Compose。当前获批目标和实测均未触发 99.9%/7×24、RPO 5 分钟、RTO 30 分钟、持续 100 RPS、不可接受单机维护或物理隔离要求。

该结论接受单主机、PostgreSQL 和 RabbitMQ 的共同故障域，使用异机备份、明确 RTO、Outbox/Inbox、告警和已演练恢复控制风险。25.015 RPS 只证明批准的 20 RPS 基线，不是最大容量结论；目标环境必须重复测量，实际持续负载达到触发条件时重新评审。

## 6. 目标环境上线前检查

以下事项属于具体部署实例化，不重新打开 M4 代码基线，但任一未完成都阻止该环境上线：

1. 使用正式 HTTPS 域名、可信证书和由密钥系统生成的 OIDC、数据库、RabbitMQ、监控、告警及备份密钥。
2. 配置主机故障域之外的加密备份存储，启用备份/保留/监控定时器并验证最近恢复点。
3. 把责任角色映射到具体主责和备份人员，验证告警 Webhook、确认时限和升级链路。
4. 在目标主机重跑完整 CI、韧性门禁、备份恢复、发布回滚和凭据轮换抽验。
5. 记录目标主机规格和首轮容量结果，确认不存在与 ADR-031 不一致的 SLO、合规或 7×24 要求。

## 7. M4.1 产品收尾补充

M4 验收后又完成了不改变生产目标的产品收尾：

- 新增受 `platform.operations.read` 权限保护的 `/portal-api/v1/operations/targets`，只返回经过完整类型和安全约束校验的非敏感生产目标。
- 平台配置页面改为只读“配置即代码”视图，数据唯一来自 `deploy/operations/production-targets.json`，不提供绕过代码评审的在线写入口。
- 门户、能力总览和导航统一到 M4 基线；备份恢复与平台配置状态反映实际交付结果。
- 删除模拟 Store、领域演示记录、原型服务页和伪成功操作；M5/M6 页面只说明未启用状态与启动条件。
- 明确当前通知只实现 `IN_APP`/`LOCAL_REFERENCE` 站内测试通道；`DELIVERED` 表示本地测试记录成功，不表示邮件、短信、Teams、企业微信等外部渠道已经投递。

该补充不改变本报告的“生产准备基线通过”结论，也不替代目标环境上线检查。
