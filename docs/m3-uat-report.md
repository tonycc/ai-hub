# M3 平台公共能力 UAT 报告

## 1. 验收结论

| 项目 | 结果 |
| --- | --- |
| 执行日期 | 2026-08-13 |
| 环境 | 全新 `standard-events` Docker Compose 环境，Traefik 统一入口 `:8088` |
| 身份链路 | authentik OIDC Authorization Code + PKCE，平台 BFF `HttpOnly` 会话 |
| 执行角色 | 平台管理员、应用开发者、安全审计员、平台运维 |
| 总体结论 | 通过；无未关闭 P0/P1 缺陷，M3 满足退出条件 |

参考应用是业务中性的接入一致性夹具，不是试点应用或平台交付的真实业务系统。UAT 只验证平台公共能力和外部应用接入边界。

## 2. 角色与任务结果

| 用例 | 角色 | 验收任务 | 结果与证据摘要 |
| --- | --- | --- | --- |
| UAT-01 | 平台管理员 | 登记一次性中性应用并配置环境 | `uat-contract-app` 登记成功；环境、入口、API、健康地址和严格回调保存成功 |
| UAT-02 | 平台管理员 | 用户、组织、平台角色、应用角色、权限点和数据范围 | 页面从真实 PostgreSQL API 加载；写入口只对管理员展示，服务端资源权限生效 |
| UAT-03 | 应用开发者 | 所属应用 API-only 接入认证 | 只看到 `standalone-example`；`API_ONLY` 认证以 `m3-conformance-0.2.0` 通过 |
| UAT-04 | 应用开发者 | 按需事件能力与开发者资产 | OpenAPI、AsyncAPI、Python SDK、接入文档和示例均带摘要；事件能力不会成为 API-only 前置条件 |
| UAT-05 | 安全审计员/管理员 | 创建、轮换和吊销凭据 | Client Secret 仅展示一次；创建 v1、轮换 v2、吊销 v3 后状态为 `REVOKED`，审计不含密钥 |
| UAT-06 | 平台运维 | 诊断应用、事件队列和投影 | 两个队列均为零积压且各有一个消费者；投影过期警告与来源/快照水位可区分；角色不能修改应用或凭据 |
| UAT-07 | 四类角色 | 权限和数据边界 | 导航按权限收敛；无权 API 返回 `403` 与 Request ID；平台不提供真实业务主表或领域规则写入口 |
| UAT-08 | 应用开发者/平台运维 | 测试通知 | 应用范围最小收件人列表可用，两次测试通知均为 `DELIVERED`；不要求全局身份读取权限 |

安全审计员仅有身份/授权读取和凭据治理能力；平台运维仅有应用、通知、审计、开发者资产和运行诊断能力。直接访问未授权身份管理路由时，API 以 `403` 失败关闭。

## 4. 验收中发现并关闭的问题

| 编号 | 现象 | 根因 | 修正与回归 |
| --- | --- | --- | --- |
| M3-UAT-001 | 全新标准事件启动偶发 `tuple concurrently updated` | 发布者与消费者数据库角色脚本并发执行 PostgreSQL 角色授权 | 消费者 bootstrap 显式依赖发布者 bootstrap；Compose 契约和全新环境复验通过 |
| M3-UAT-002 | 管理列表在真实 PostgreSQL 返回 500 | `NULL` 可选参数在原生 SQL 中缺少可推断类型 | 所有可选字符串、UUID、数组和时间过滤器使用显式 `CAST`；真实页面与静态契约通过 |
| M3-UAT-003 | 应用开发者无法选择测试通知收件人 | 收件人选择错误依赖全局 `platform.identity.read` | 新增应用范围的最小收件人 API，仅返回 user id、subject、display name；开发者和运维实测送达 |
| M3-UAT-004 | 凭据吊销已更新 authentik，但门户返回 500 | 服务行含父级 join 字段，严格响应模型拒绝额外字段，随后数据库事务回滚 | 改为响应字段白名单映射并添加回归测试；复测显示 `v3 · REVOKED` |

Docker Desktop 磁盘空间不足属于本机测试环境问题，通过官方缓存清理和重启恢复；未删除仓库文件或持久业务数据，不计为产品缺陷。

## 5. 已知非缺陷状态

- 运维总览显示“降级”是因为参考应用尚未上报入口健康检查，诊断信息明确，不代表平台 API 不健康。
- 投影新鲜度可显示警告，因为 UAT 后没有新的来源事件；队列已排空且消费者在线。
- `PLATFORM_CONFIG`、备份恢复、告警、SLO/RPO/RTO 属于 M4 生产准备范围，不计入 M3。

## 6. 发布结论与下一步

M3 可以结束并进入 M4。下一步先执行 M4-01：冻结服务窗口、SLO、RPO、RTO、数据保留期和部署档位，再开展备份恢复、告警、发布回滚与故障演练。
