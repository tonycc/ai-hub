# AI Hub 平台前端设计与复用说明

页面布局、工具栏、列表、卡片、详情、表单、状态反馈和响应式行为统一遵循[管理端前端页面设计规范](admin-frontend-design-spec.md)。本文档只定义平台门户和平台管理端，不定义或交付任何真实业务应用页面。

## 1. 范围与定位

平台前端服务四类主要角色：平台管理员、应用开发者、安全审计人员和平台运维人员。它用于管理公共能力、观察平台状态并帮助独立应用完成标准接入，不承载应用的领域字段、状态机、规则、报表和业务操作。

正式建设范围包括：

- 平台门户与应用入口。
- 用户、组织、角色、权限点和数据范围管理。
- 应用注册、环境入口、回调白名单、能力集、scope、凭据和版本生命周期管理。
- 站内测试通知配置、测试送达和发送结果查询；不把本地送达状态表述为外部消息渠道已投递。
- API、事件、服务身份、对象引用和平台投影的接入治理。
- 操作、授权、凭据和公共能力调用审计。
- 健康、指标、告警、发布、备份恢复和容量状态。
- OpenAPI、AsyncAPI、Python SDK、沙箱、本地替身和接入认证结果。

企业语义与 AI 管理页面分别按 V1.1 和 V1.2 的已批准需求启动。统一待办、通用工作流、通用表单和文件服务只有正式进入平台产品范围后才增加，不作为 V0.1、V0.5 或 V1.0 的隐含前置条件。

历史领域演示路由、视图、Store、模拟数据和伪成功操作已经从平台制品删除。后续不得重新引入无法由正式 API 证明的数据与操作，也不得将领域模型迁入平台 API 或数据库。

## 2. 设计目标

平台前端需要持续满足：

1. 平台管理员能从一个入口完成公共配置和治理任务。
2. 应用开发者能仅依赖公开文档、SDK 和沙箱完成首次接入。
3. 用户身份、服务身份、scope、凭据、回调和事件权限的边界可见且可审计。
4. 每个应用的入口、版本、健康状态和接入能力可以独立管理。
5. 平台故障、应用故障和外部依赖故障能被区分并给出可执行的处理建议。
6. 前端不会通过隐藏按钮代替服务端鉴权，也不会持有服务身份凭据或直接连接事件基础设施。

## 4. 版本交付范围

### 4.1 V0.1 接入骨架

- 平台应用壳层、登录态、首页和应用中心。
- 应用登记、入口、回调、健康和接入能力的最小查看与配置。
- 统一的加载、空数据、错误、无权限和依赖不可用状态。
- request_id 展示与问题反馈入口。
- 中性参考应用的跳转、授权和 API 调用状态页。

### 4.2 V0.5 平台公共能力

- 用户与组织、权限与安全、通知、审计和接入治理工作台。
- 应用凭据创建、轮换、撤销和敏感值一次性展示。
- 开发者中心、契约版本、SDK 示例、沙箱和接入认证报告。
- API-only、事件发布、事件消费和平台投影四类能力配置及其依赖提示。

### 4.3 V1.0 生产治理

- SLO、健康、指标、告警、队列积压和应用级配额。
- 发布、回滚、凭据轮换、备份恢复和演练记录。
- 公共依赖故障、应用不可用、投影过期和恢复进度的状态反馈。
- 生产目标以受版本控制的配置文件为唯一来源；管理端只读展示，不提供在线修改入口。

## 5. 核心交互

### 5.1 平台管理员

1. 创建或同步用户与组织。
2. 创建角色并授予应用权限和数据范围。
3. 注册应用及环境，配置入口、回调和健康检查。
4. 为应用启用最小能力集和 scope。
5. 查看配置变更与调用审计。

### 5.2 应用开发者

1. 登记开发环境和回调地址。
2. 获取公开契约、SDK 和沙箱配置。
3. 先以 `API_CLIENT` 完成用户身份、权限和测试通知接入。
4. 按需申请事件发布、事件消费或平台投影能力。
5. 运行认证测试并查看失败项、证据和修复建议。
6. 轮换凭据并确认旧凭据已撤销。

### 5.3 安全与运维

1. 查询授权、凭据和敏感配置的变更记录。
2. 识别异常 scope、错误 audience、过期凭据和高频拒绝。
3. 查看服务健康、事件积压、投影水位、备份和恢复状态。
4. 按应用停用入口或凭据，并验证故障未扩散到其他应用。

## 6. 页面与组件约束

- 使用项目已有应用壳层、Element Plus 组件和 Design Token，不为单页建立平行视觉体系。
- 页面标题只出现一次；筛选靠左，主要操作靠右，内容区和表格默认占满可用宽度。
- 列表使用项目数据表格组件，必须覆盖加载、空数据、错误、无权限和部分数据过期状态。
- 无写权限时不渲染写操作；敏感字段按读取权限返回和展示，不能先返回完整值再由前端隐藏。
- Client Secret 等敏感值只允许创建时一次性展示；复制动作必须有反馈并留下审计。
- 凭据撤销、应用停用、环境删除和破坏性配置变更必须二次确认，并说明影响对象与恢复方式。
- 状态不能只靠颜色表达；图标按钮必须有可访问名称，弹窗和表单必须支持键盘与焦点管理。
- 桌面 Web 是 V0.5/V1.0 正式支持范围；移动端适配另行立项。

## 7. 前端代码边界

目标平台前端结构建议保持：

~~~text
src/
├── components/       平台通用组件，不含领域状态
├── layouts/          平台应用壳层、导航和全局反馈
├── router/           仅注册平台目标路由
├── services/         版本化平台 API 客户端
├── stores/           平台会话状态；不得保存模拟业务或治理记录
├── styles/           Design Token 与组件基础覆盖
└── views/            门户及平台管理页面
~~~

允许复用布局、状态标签、指标卡、表格工具栏、CSS Token、响应式断点和无业务语义的表单组件。不得复用历史领域页面、领域 Store、领域模拟数据、状态转换或业务校验。

页面调用层次保持：

~~~text
Vue 页面 / 组件
    ↓
平台 Store 或 Query Composable
    ↓
平台 Service
    ↓
版本化平台 API
~~~

前端不得访问其他应用数据库、内部接口、RabbitMQ 或服务身份密钥。平台 API 是管理端数据与操作的唯一正式入口。

## 8. 接口与权限约束

- OpenAPI 是平台前端接口事实来源，页面不得自行猜测字段或拼接未登记地址。
- 平台后端验证 authentik 签发令牌的签名、issuer、audience、有效期和 scope；前端路由守卫只改善体验，不构成安全边界。
- 每个写操作携带 request_id、目标资源版本或等价并发控制信息，并清楚处理冲突、超时和部分失败。
- 错误反馈说明对象、原因和下一步；不得只显示“操作失败”。
- 平台投影页面必须展示来源应用、来源版本、最后同步时间和过期状态，且不提供修改来源业务状态的操作。

## 9. 验收任务

V0.5 前至少完成以下角色任务测试：

1. 平台管理员注册一个中性参考应用并配置开发环境。
2. 平台管理员创建角色、分配权限和数据范围，并确认无权用户看不到写操作。
3. 应用开发者找到 OpenAPI、SDK、沙箱参数并完成 API-only 认证。
4. 应用开发者按需启用事件能力，理解 Outbox/Inbox 的适用条件而不会被强制启用。
5. 安全人员轮换并撤销服务凭据，确认旧凭据调用失败且审计完整。
6. 运维人员定位一个应用不可用、事件积压或投影过期问题，并找到运行手册。
7. 所有角色能够区分平台配置、平台只读投影和外部应用业务数据。

记录任务完成率、耗时、误操作、术语理解和缺失信息，据此冻结正式页面范围和 API 契约。真实业务应用的页面、数据、流程与用户验收不属于本轮验收。
