# ADR-032：以定期增量数据汇聚替代 M2 实时事件投影

- 状态：已接受并已实施（M7-01 ~ M7-06）
- 决策日期：2026-08-16
- 决策范围：平台"应用数据向平台汇聚"能力的实现方式与 M2 实时事件投影能力线的存续
- 详细方案：[`../incremental-data-ingestion-design.md`](../incremental-data-ingestion-design.md)

## 背景

平台的真实业务需求是：**各业务应用把数据定期同步到平台，平台综合各应用数据进行统一治理，并提供给 AI 使用**。关键约束是**定期增量同步**（分钟/小时/天级），**无秒级实时性要求**。

M2 已建设的实时事件投影链路（RabbitMQ + 应用侧 Outbox/Inbox + 平台投影 Worker + `platform_projection` Schema）为零丢失与秒级时效付出了显著复杂度：

- **接入耦合重**：每接入一种业务对象，平台端都要建专属投影表、编写投影逻辑、登记事件契约——接入新应用的边际成本高。
- **基础设施重**：引入 RabbitMQ、Outbox、Inbox、独立投影 Worker 及配套的可靠性演练。
- **能力错配**：其提供的"可靠传播业务事实、秒级时效"正是当前业务不需要的；对"定期全量/增量汇聚"而言是净负担。

M2 解决的是"实时、不丢、不错"的问题，而当前需求只需要"定期、覆盖/增量、可回溯"。需要决策：是否保留 M2，或以更轻的方式承接数据汇聚职责。

## 决策

**下线并删除 M2 实时事件投影能力线，以"贴源层（Raw/ODS）+ 平台拉取 + 位点"的定期增量数据汇聚承接其数据汇聚职责。** 详见[设计方案](../incremental-data-ingestion-design.md)，要点：

1. **贴源层（Raw 层）**：平台端用通用的 `platform_raw` Schema（`raw_sync_cursor` / `raw_ingest_batch` / `raw_change_record` / `raw_current_state`）原样接收各应用数据，**接入新应用/新对象平台端零定制建表**。
2. **平台拉取（Pull）**：调度器按周期拉取应用的增量导出接口，位点由平台集中管理，应用无状态。
3. **增量语义三件套**：`operation`（upsert/delete，删除显式可见）、`(应用, 对象类型)` 全序单调 `version`（防乱序 + 位点推进）、幂等唯一约束（防重复）。
4. **正确性保障**：安全回看窗口防并发事务版本倒挂丢数据；full 批次"缺席即权威"合成墓碑传播删除；当前态普通表批内同事务维护。
5. **payload 契约化**：每个 `object_type` 的 payload 为显式登记的版本化契约（字段筛选/脱敏），不退化为共享数据库集成。
6. **纯 HTTP**：不引入 RabbitMQ / Outbox / Inbox；部署只保留 `base-access` 档位。

**退役执行顺序**：先建成增量汇聚并验收达标（M7-01 ~ M7-05），再执行 M2 退役（M7-06），避免能力真空期。M2 退役为**单向操作**，须先建成增量汇聚并验证达标。

## 备选方案（未选择）

### 保留 M2，与增量汇聚并存

未选择。两条能力线同时维护会加倍契约、认证、CI 与运维成本；M2 的实时能力当前无业务需求，保留即持续负担。

### 保留 M2，仅在其上叠加批量导出

未选择。M2 的强类型逐对象投影表仍是接入耦合的根源；在其上叠加批量导出无法解决"每应用建表"的成本，反而引入两套数据入口。

### 直接用 CDC / 数据库日志复制

未选择。违反平台红线——平台不得直连应用数据库扫表或订阅原始日志；数据必须经应用治理、脱敏、版本化为稳定契约后导出，不能依赖来源表名与列结构。

## 后果与风险控制

| 后果或风险 | 控制措施 |
| --- | --- |
| 失去实时事件能力，未来若出现实时需求需重建 | 事件契约与代码经 git tag 归档；重建时以归档为基线，并按届时需求重新评审 |
| 时效性降为同步周期级 | 已与业务确认满足需求；同步周期按对象类型可配 |
| 增量正确性依赖 version 全序单调与位点稳定 | 契约硬要求 + 安全回看窗口默认 + 一致性认证"并发写入无漏拉"检查项 |
| full 重建删除传播 | "缺席即权威"合成墓碑 + `high_watermark` 契约澄清，认证覆盖 |
| 汇聚退化为共享数据库集成 | payload 契约化硬要求 + 退化预警 + 认证/评审拦截 |
| M2 退役影响 M4 含 RabbitMQ/投影的演练项 | M7-06 同步修订 M4 相关运行时脚本与报告基线；备份/恢复不再含 RabbitMQ 与投影库 |

## 复核机制

- 增量汇聚验收（M7-05）达标是执行 M2 退役（M7-06）的前置闸门。
- 退役后：全仓检索（限定代码/配置路径）确认无 RabbitMQ/Outbox/Inbox/projection/`standard-events` 残留；`base-access` 从全新数据卷启动通过 M1 与 M7 全部门禁。
- 若未来出现已批准的实时数据传播需求：停止以批量汇聚承接该场景，重新打开本 ADR 评审是否恢复事件能力（可参考归档契约）。
